# SubsTracker — 訂閱管理與提醒系統

基於 **Cloudflare Workers + KV** 的輕量級訂閱到期提醒。在網頁裡管理訂閱，到點通過 Telegram / Bark / 企業微信 / ntfy 等 **11 種渠道** 推送，並自帶傳送與排程日誌方便排查。

**適合**：個人自託管、域名/會員/賬單到期提醒。\
**不適合**：多使用者協作、複雜企業審批流。

## 🚀 5 分鐘上手

```text
部署 Worker
  → 用 admin / password 登入（立刻改密碼）
  → 系統配置：選時區（中國選 Asia/Shanghai）
  → 系統配置：允許傳送的小時（例如只想早上 8 點發就填 08）
  → 勾選至少一種通知渠道並填好 Token，點「測試」直到成功
  → 訂閱列表：新增訂閱（可用預設提醒預設 7/3/1 天 + 當天）
  → 到點後去「通知歷史」看是否傳送 / 為何跳過
```

若中途卡住，先看下方 [常見問題 FAQ](#-常見問題-faq)。

## 📦 部署

### 方式一：命令列（推薦）

```bash
git clone https://github.com/wangwangit/SubsTracker.git
cd SubsTracker
npm install

# Linux / macOS
export CLOUDFLARE_API_TOKEN=你的token
# Windows PowerShell
# $env:CLOUDFLARE_API_TOKEN="你的token"

npm run deploy:safe
```

`deploy:safe` 會：

1. `npm run setup` — 自動建立 / 繫結 KV（`SUBSCRIPTIONS_KV`）
2. `npm run deploy` — 部署 Worker

部署成功後，終端會列印類似：

`https://subscription-manager.<你的子域>.workers.dev`

### 方式二：GitHub Actions

1. Fork 本倉庫\
2. 倉庫 **Settings → Secrets and variables → Actions** 增加：

| Secret | 說明 |
|--------|------|
| `CLOUDFLARE_API_TOKEN` | 需 Workers 編輯 + KV 編輯許可權 |
| `CLOUDFLARE_ACCOUNT_ID` | 可選 |

3. 推送到 `master` / `main` 或手動執行 **Deploy** workflow\

### 預設登入

| 項 | 值 |
|----|-----|
| 使用者名稱 | `admin` |
| 密碼 | `password` |

**登入後請立刻在「系統配置」修改密碼。** 公網暴露預設密碼會被接管。

### 忘記密碼

Cloudflare Dashboard → **Workers & Pages → KV** → 開啟 `SUBSCRIPTIONS_KV` → 編輯 key `config` 的 JSON，修改 `ADMIN_PASSWORD` 後儲存。

## ✅ 第一次必做配置

開啟 **系統配置**，建議按順序做完：

### 1. 改密碼

管理員使用者名稱 / 密碼改成自己的。頁面若提示仍是預設 `admin`，請務必處理。

### 2. 時區

- 中國大陸使用者：**`Asia/Shanghai`（北京時間）**
- 所有「到期還有幾天」「幾點發通知」都以這裡為準

### 3. 允許傳送的小時

| 你填什麼 | 含義 |
|----------|------|
| `08` | **僅**北京時間 **8 點那一小時**會發（約 8:00–8:59 的那次整點檢查） |
| `08, 20` | 早上 8 點、晚上 8 點各可能發一次 |
| **留空** 或 `*` | **每個整點**都可以發 |

要點：

- 系統大約 **每小時整點** 檢查一次（Cron：`0 * * * *`，按 UTC 觸發，但判斷用你配置的時區）。
- 填了 `08`、現在是 19 點：**不會發**。通知歷史裡出現「不在允許傳送的小時」是 **正常跳過**，不是壞了。
- 配置頁下方有即時預覽（會顯示「當前會發 / 不會發」）。**改完要點儲存**，預覽才與伺服器一致。

### 4. 開啟至少一種通知渠道

勾選渠道 → 填 Token / Chat ID 等 → 點 **測試 xxx 通知**，確認手機/群裡能收到。

常用渠道簡表：

| 渠道 | 你需要準備 |
|------|------------|
| Telegram | Bot Token + Chat ID；Forum 群可選 Topic ID |
| Bark | Device Key；自建可填 Server |
| 企業微信 | 群機器人 Webhook |
| ntfy | Server（預設 ntfy.sh）+ Topic；可選 Token |
| WPUSH | API Key；可選 Channel / Topic 編碼 |
| 郵件 | Resend API Key + 收發郵箱 |
| Webhook | 任意 HTTP 地址 + 可選模板 |

### 5. 加一條測試訂閱

- 到期日設近一點，提醒規則可用 **「應用預設 7/3/1/當天」**
- 或臨時加一條「到期前 0 天 / 到期當天」，並把「允許傳送的小時」改成當前小時做聯調（測完改回）

## 📋 日常怎麼用

### 訂閱列表

| 操作 | 說明 |
|------|------|
| 新增 / 編輯 | 名稱、週期、金額、分類、農曆等 |
| **克隆** | 複製一條（名稱帶「副本」），適合 esim 保號等同構訂閱 |
| 續訂 | 手動延長週期並記支付 |
| 停用 / 啟用 | 停用後不再提醒（本地重新整理，不必整頁過載） |
| 測試 | 立刻對該訂閱發一條測試通知 |
| 歷史 | 支付記錄 |
| 篩選 | 關鍵詞、迴圈/重置模式、**狀態**（正常/即將到期/已過期/已停用）、分類 |

### 提醒規則（每條訂閱可多條）

預設預設：**到期前 7 天、3 天、1 天 + 到期當天**。

**重要語義（很多人誤解這裡）：**

> 「到期前 N 天」= **剩餘天數正好等於 N 的那一天發一次**\
> **不會**從第 N 天起每天連發。

若要 7、6、5… 都提醒，需要多條規則，或使用預設 7/3/1/當天。

其它型別：

- **到期當天**
- **到期後**：每隔 X 小時提醒，直到你續費（受「允許傳送的小時」約束）

### 訂閱模式：迴圈 vs 到期重置

| 模式 | 一句話 | 例子 |
|------|--------|------|
| **迴圈訂閱** | 未過期就從**當前到期日**往後接 | 會員 6/15 到期，6/3 續費 → 新到期約 7/15 |
| **到期重置** | 從**支付日**重新算一整段週期 | 保號卡充值日重新起算 180 天 |

### 週期快捷

表單裡可用 **季度 / 半年 / 一年** 快捷（本質是 3 個月 / 6 個月 / 1 年）。\
公曆可勾選 **「每月最後一天」**（適合「每月月末提醒」；農曆下不用這個）。

### 備份與遷移

在 **系統配置** 最下方：

1. **匯出備份** → 下載 JSON（預設可不含金鑰）
2. 換賬號 / 重灌後 **匯入**\
   - **合併**：按訂閱 ID 覆蓋同名，保留其它\
   - **覆蓋**：先清空再整包匯入（危險，先匯出當前資料）

升級大版本或遷移 CF 賬號前，**先匯出一份**。

## 🔔 通知到底怎麼工作（重點必讀）

```text
每小時整點 Cron
  → 看現在是否在「允許傳送的小時」（按時區）
  → 看每條啟用中的訂閱是否命中某條提醒規則（精確日/小時）
  → 去重（同一天同一規則不重複刷）
  → 發到你啟用的渠道
  → 寫入「通知歷史」+「排程日誌」
```

「允許傳送的小時」是傳送視窗。例如填 `08, 12`，命中同一條日級規則後通常只在 08 點發送一次，12 點不會重複傳送；它不是每天傳送兩次的計劃。

| 現象 | 通常原因 |
|------|----------|
| 任務歷史：不在允許傳送的小時 | 當前整點不在你填的 `08` 等列表裡 → **正常** |
| 在視窗內但 sentCount=0 | 今天沒有規則被命中（還沒到「正好 N 天」） |
| 有 failed 記錄 | 渠道配置錯 / Token 失效 / 網路拒絕 → 看錯誤詳情 |
| 一天只在 8 點附近收到 | 你只配置了 `08`，符合預期 |
| 希望一天提醒多次 | 把允許小時寫成多個，如 `08, 12, 20`，或留空 |

**列表上的「提醒」列**：顯示該訂閱真實多規則摘要（如 `提前 7/3/1 天 · 到期當天`），與後臺 `reminder_rules` 一致。

## ❓ 常見問題 FAQ

### 1. 為什麼沒收到通知？

按順序查：

1. **系統配置**是否啟用了渠道？「測試」能否收到？\
2. **允許傳送的小時**是否包含「現在」？（填了 `08` 則只有 8 點）\
3. **時區**是否是 `Asia/Shanghai`？\
4. 該訂閱是否 **啟用**？提醒規則是否啟用？\
5. 今天是否正好命中「到期前 N 天 / 當天」？\
6. 開啟 **通知歷史**：\
   - 有 failed → 看渠道報錯\
   - 只有跳過、寫著不在允許小時 → 等到配置的小時\
   - 完全沒有相關記錄 → 可能還沒到整點檢查，或規則未命中\

### 2. 任務歷史寫「不在允許傳送的小時 / 不在配置時段」？

說明定時任務跑了，但當前小時不允許發。\
例如只允許 `08`，晚上 19 點跳過 → **正常**。\
到北京時間 8 點再看是否傳送。

### 3. 設定了「到期前 7 天」，為什麼第 6～1 天沒有通知？

這是 **精確日** 設計：只在剩餘 **正好 7 天** 那天發。\
需要多天提醒請加多條規則，或用預設 **7/3/1/當天**。

### 4. 列表提醒一直顯示「提前 7 天」？

當前版本列表會讀真實規則摘要。請 **強制重新整理**（Ctrl+Shift+R）。\
若仍不對，開啟瀏覽器開發者工具 → Network → `subscriptions`，看返回裡是否有 `reminderRulesSummary`。

### 5. 克隆按鈕看不見或沒顏色？

操作列有 **克隆**（青色）。強制重新整理；按鈕在「編輯」後面。\
若只有灰字，確認已部署含主題樣式的最新版本。

### 6. 迴圈訂閱和到期重置有啥區別？

見上文表格：會員續費用 **迴圈**；按充值日重算週期用 **重置**。

### 7. 如何備份 / 換 Cloudflare 賬號？

系統配置 → **匯出備份** → 新環境部署後 **匯入**。\
覆蓋模式會清空現有訂閱，操作前再匯出一次當前資料。

### 8. Telegram 如何發到群話題（Topic）？

系統配置 → Telegram → 填寫可選 **Topic ID**（對應 `message_thread_id`）。\
普通私聊/普通群可留空。

### 9. ntfy 怎麼配？

啟用 ntfy → Server 預設 `https://ntfy.sh` → 填自己的 Topic → 手機 ntfy App 訂閱同一 Topic → 點測試。

### 10. WPUSH 怎麼配？

啟用 WPUSH → 在 [設定頁](https://wpush.cn/settings) 獲取 API Key → 可選填寫渠道 / Topic 編碼 → 點測試。成功條件為介面返回 `code === 0`。

### 11. 控制台裡 `beacon.min.js` / cloudflareinsights 報錯？

那是 **Cloudflare 統計指令碼**，不是本專案業務程式碼。一般可忽略，與訂閱列表無關。

### 12. Authentication error [code: 10000]（部署時）

Token 許可權不足或 Wrangler 快取問題：檢查 API Token 許可權，必要時刪 `.wrangler/` 後重試。

### 13. 第三方系統想調通知介面？

在系統配置生成 **第三方 API 令牌** 後：

```bash
curl -X POST "https://你的域名.workers.dev/api/notify/你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"title":"標題","content":"正文"}'
```

也可用請求頭：`Authorization: Bearer 你的令牌`。

## 🔐 安全提醒

1. **立刻修改** 預設 `admin` / `password`\
2. 不要把 API Token、Bot Token 提交進 Git\
3. 備份 JSON 若勾選「包含敏感配置」，請當密碼一樣保管\
4. 對話、截圖裡不要長期暴露 Cloudflare API Token；洩露請到 Dashboard **輪換 Token**
